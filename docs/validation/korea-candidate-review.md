점수는 검토 작업의 순서를 위한 규칙 기반 합계이며 **전기적 접속 확률이나 신뢰도 확률이 아니다**. 설비 존재·차단기 상태·운영 토폴로지를 증명하지 않는다.

| 관측 근거 | 가점 |
|---|---:|
| 모선 간 거리 ≤50 / ≤100 / ≤200 / ≤500 / >500 m | 30 / 24 / 16 / 8 / 0 |
| 두 모선 모두 실제 변전소 폴리곤 내부 또는 경계 | 20 |
| 변전소 및 양측 모선의 모든 입사 선로 전압 태그가 명시적이며 후보 전압 포함 | 15 |
| 두 모선 모두 차수 1 | 10 |

경계 누락, 경계 밖 모선, 전압 태그 누락/불일치, 병가 지지물 검토 표식에 대해 경고 종류마다 10점을 감점한다. 최소 점수는 0이다. 전압 태그에 `154000;345000`처럼 여러 값이 있으면 후보 전압이 포함되는지 검사한다. 알 수 없는 값·단위 문자열·비유한 값은 일치로 간주하지 않는다. 누락된 태그에서 전압을 추정하지 않는다. 경고가 관측되지 않아도 전기적 접속 확인은 아니다.

## 지도와 외부 입력 처리

모선의 위경도와 원본 선로의 **모든 경로 꼭짓점**을 사용한다. 선택한 두 성분을 청록색/주황색으로, 주변 다른 성분을 회색으로 구분한다. 실제 변전소 Polygon/MultiPolygon은 보라색으로 표시한다. 초깃값은 변전소 경계와 후보 모선을 중심으로 맞추며, 휠/버튼 확대·축소와 드래그 이동을 지원한다. 확대 시 모선 표식과 거리 글자의 화면상 크기를 유지해 수 미터 간격도 조사할 수 있다. SVG는 국소 등거리 원통 투영으로 표시하므로 광역으로 크게 축소하면 왜곡이 커진다. 지도는 변전소 주변 검토용이다. 배경 지명·도로·항공영상은 제공하지 않는다.

### 지도 범위 변경 후 설비 누락 수정 (2026-10-26)

기존 `drawMap()`은 최초 화면의 모선과 최초 범위 주변의 선로만 SVG에 생성했고, 이후 확대·축소·드래그는 `viewBox`만 바꿨다. 고강변전소에서 축소 9회 후 실제 화면 안 모선이 8개로 늘어나도 최초 2개만 남는 문제를 수정했다. 새 회귀 테스트를 수정 전 코드에 적용하면 바로 이 단계에서 실패하는 것을 실제 Chrome으로 확인했다.

- 모선 위치와 선로 경로의 위경도 경계 상자로 공간 인덱스(BVH)를 한 번 구축한다. 이동 중에는 현재 화면의 지리 범위로 인덱스를 조회한다.
- 선로는 경계 상자 조회 후 실제 경로 선분과 화면 사각형의 교차를 검사한다. 양 끝점과 모든 꼭짓점이 밖에 있어도 경로가 화면을 통과하면 표시하며, 경계 상자만 겹치는 선로는 제외한다.
- 화면에 새로 들어온 설비를 추가하고 나간 설비를 DOM에서 제거한다. 기존 모선·선로 노드는 재사용하고, 방문한 경로의 SVG도 후보 선택 동안 캐시한다. 전국 데이터의 SVG를 이동마다 재생성하지 않는다.
- `requestAnimationFrame`으로 연속 입력을 프레임당 한 번의 설비 갱신으로 합친다. 선택 후보 모선의 흰 테두리와 두 연결 성분의 청록/주황 강조를 유지한다. 후보 모선은 화면 밖에서도 SVG에 유지하되 화면 경계에서 잘린다.
- 후보를 바꾸거나 변전소 맞춤을 실행하면 이전 대기 프레임과 투영 캐시를 정리해 다른 후보의 설비가 섞이지 않게 한다.

실제 1600×1200 Chrome 창에서 독립적인 전체 좌표·선분 대조로 다음을 확인했다. 아래 숫자는 선택 후보를 화면 밖에 별도로 유지하는 노드를 제외한 실제 화면 내 설비 수이다.

| 변전소 | 최초 모선 / 선로 | 축소 9회 후 모선 / 선로 |
|---|---:|---:|
| 고강 `way/887782992` | 2 / 3 | **8 / 7** |
| 신옥천 `way/156580308` (연결 성분 8개) | 29 / 30 | **35 / 35** |

`tests/browser/candidate_review_viewport_probe.js`와 `tests/test_kr_candidate_review_browser.py`에 고강·신옥천의 축소, 재확대, trusted 포인터 드래그, 맞춤, 대기 프레임 중 후보 변경을 추가했다. 매 단계의 화면 내 모선과 교차 선로를 원본 전국 좌표로 독립 계산하여 대조하고, 새 설비 추가·화면 밖 설비 제거·강조·메모 보존을 확인한다. 기존 SVG 노드의 동일성, 확대 중 전국 모선/선로 순회 없음, 연속 입력 24회의 설비 갱신 1회도 검사한다. 별도 합성 데이터는 꼭짓점이 모두 화면 밖인 교차 선로와 경계 상자만 겹치는 비교차 선로를 구분한다. 기존 JSON 다운로드·업로드, 필터·검색, 다른 입력 버전 기록 격리 프로브도 함께 실행한다.

실제 결과는 `outputs/kr_topology/review/browser/viewport-way-{887782992,156580308}.json`에 저장한다. 이번 수정 범위는 검토용 `review.js`, 관련 브라우저 테스트/프로브 및 이 검증 문서이다. 생성기, 검토 키·입력 해시·검토 상태 스키마, EMS와 전기적 모델에는 변경이 없다.

붉은 점선은 후보 모선 사이 측정 거리 주석이다. 모델 선로가 아니며, 원본 그래프에 추가하지 않는다. 거리 값은 기존 분석의 대권거리(haversine, 평균 지구 반지름 6,371,008.8 m), 소수 둘째 자리 미터를 유지한다. 화면의 국소 투영 길이로 다시 계산하여 덮어쓰지 않는다.

원본 추출은 경계와 접하는 모선도 변전소 소속으로 취급한다. 단순 ray casting은 경계 위 끝점을 밖으로 분류할 수 있어 별도 경계 선분 포함 검사를 사용한다(1e-10도, 약 0.01 mm 수치 허용오차; 근접 모선을 포함시키는 버퍼가 아님). 실데이터의 384건 모두 양측 모선이 폴리곤 내부/경계에 있다. 폴리곤이 없으면 임의 도형 없이 지리 정보 없음으로 표시한다.

선로·모선·변전소를 클릭하면 원본 OSM ID·태그·형상·전압·성분 등 상세 정보를 보여준다. 변전소 상세에는 경계 안 관련 transformer/busbar/switch/switchgear 객체도 표시한다. 점과 LineString 꼭짓점의 경계 포함으로 조사하므로, 모든 꼭짓점이 밖에 있으나 경계를 통과하는 설비는 누락될 수 있다. 원본에 해당 객체가 없으면 설비 부재라고 판단하지 않는다.

OSM 이름과 태그, 가져온 메모는 DOM `textContent` 또는 폼 `value`로 표시한다. 내장 JSON의 `<`, `>`, `&`, Unicode 줄 구분자를 이스케이프해 script 종료 삽입을 막는다. CSP는 외부 스크립트·네트워크 연결·객체 삽입을 차단한다. 출처 문자열을 링크나 실행 코드로 해석하지 않는다. CSV는 수식 실행을 유발할 수 있는 접두문자에 작은따옴표를 붙인다.

## 검토 상태와 기록 가져오기/내보내기

| 코드 | 화면 상태 | 의미 |
|---|---|---|
| `unreviewed` | 미검토 | 검토 기록 없음 또는 미검토로 기록 |
| `needs_information` | 추가 자료 필요 | 현 데이터로 판정할 수 없음 |
| `osm_review_needed` | OSM 태그·형상 검토 필요 | 원본 객체 및 형상 재확인 필요 |
| `electrical_evidence_obtained` | 전기적 접속 근거 확보 | 사람이 근거를 기록함. 모델 연결 승인 아님 |
| `confirmed_not_connected` | 실제 연결 아님으로 확인 | 사람이 비접속 근거를 기록함 |

상태·메모·자료 식별자/경로는 브라우저 메모리에 임시 저장한다. 창을 닫기 전에 **검토 JSON 내보내기**를 누른다. 기본 다운로드 이름은 `review_decisions.json`이며 실제 저장 위치는 브라우저 다운로드 설정을 따른다. 생성된 `review/` 폴더에 수동 보관해도 된다. 내보내기는 편집/가져오기한 레코드만 포함하며, 수정한 기록의 `reviewed_at`은 내보내기 시점에 시간대를 포함해 기록한다. 기본 후보 데이터에는 시각이 없다.

새로 연 화면의 **검토 JSON 불러오기**에서 파일을 선택하면 스키마, 입력 해시, 검토 키, 상태, 모선/성분/변전소 ID, 시각, 문자열 타입/크기를 검사한다. 현재 메모와 서로 다른 같은 버전 기록, 중복 키, 잘못된 식별자는 파일 전체를 거부한다. 현재 기록을 먼저 내보내고 새 화면에서 원하는 파일을 불러오면 된다. 서로 다른 기록의 자동 덮어쓰기는 하지 않는다. 파일 크기 제한은 20 MB, 메모·출처는 각각 20,000자이다. 내보낸 파일 자체에 OSM 태그/메모를 그대로 포함할 수 있으므로 기록 내용은 JSON 데이터로 취급한다.

## 결정적 식별과 입력 변경 정책

`KR-TOPO-xxxxx`는 표시용이다. 영구 식별은 다음으로 구성한다.

1. 성분 fingerprint: 정렬한 모든 모선 ID와 선로 ID·무방향 끝점의 SHA256.
2. identity key: 변전소 OSM ID + 정렬한 성분 fingerprint 쌍 + 후보 모선 ID 쌍 + 전압의 canonical JSON SHA256.
3. 입력 해시: 원본 지도 파일 SHA256 + 선택적 OSM 객체 파일 SHA256 + 분석 CSV 전체 행의 canonical 데이터. 표시용 `candidate_id`와 행 순서는 제외한다.
4. 검토 키: `kr-review-v1:<입력 해시>:<identity key>`.

그래서 CSV 표시 번호 변경/행 순서 변경으로 키가 달라지지 않지만, 근거·지도·원본 토폴로지가 바뀌면 입력 버전이 달라진다. 지도는 파일 전체 해시를 사용하므로 무관한 태그나 포맷 변경도 보수적으로 재검토를 요구한다. 해시는 무결성 대조용이며 전자서명이나 검토자 신원 증명은 아니다.

다른 입력 버전의 기록은 `stale_records`로 보관하고 `re_review_required=true`를 붙인다. 과거의 접속 근거 확보 상태를 현재 후보에 적용하지 않는다. 같은 identity 또는 같은 변전소·후보 모선 쌍을 찾을 수 있으면 해당 후보에 재검토 표식을 표시한다. 토폴로지 변경으로 대응하지 못하는 기록도 전체 보관 목록에서 볼 수 있고 다시 내보내면 유지된다. 사람이 현 입력을 검토한 후 새 기록을 작성한다. 현재 버전에서 대응 키가 없으면 오류다. 과거 파일의 원본 데이터까지 복원·검증하는 기능은 제공하지 않는다.

## 남은 자료와 모델 반영 요건

이 도구로 지리 위치·태그의 일관성·중복 근거는 직접 확인할 수 있다. 전기적 접속을 확인할 후보는 운영기관의 동일 시점 단선도·모선 배치와 후보 인출구 대응, 회선/설비 ID, 차단기·단로기 상태까지 대조할 수 있는 경우이다. 현재 이 운영자료는 제공되지 않았으므로 어떤 후보도 전기적으로 승인하지 않았다.

추가 OSM 조사에는 busbar·switch·switchgear와 station relation, 누락 전압 및 회선 태그, 객체 버전 이력이 필요하다. 변전소 전압 태그가 최고 전압만 담는지 확인하고 병가 철탑의 과연결 가능성도 별도 조사해야 한다. 위성/항공영상은 물리 배치를 보완할 수 있지만 개폐 상태와 전기적 결선을 확정하지 못한다.

향후 모델 반영은 이 화면과 분리된 승인 절차가 필요하다. 검증된 모선/설비 대응·자료 출처·운전 시점·승인자, 대상 입력 해시, 명시적인 연결 정의와 변경 이력, 전압/모선 구획/변압기 권선 대응, 실제 회선 수 및 임피던스·정격·탭 등 파라미터를 갖춰야 한다. 복제된 별도 모델에 적용한 뒤 과연결/단락/섬·전압·파라미터 검증, 기준 스냅샷 비교, AC PF 적합성 검증 및 롤백 경로를 확보해야 한다. 이 절차 전에는 검토 JSON을 모델 명령으로 소비하지 않는다.
